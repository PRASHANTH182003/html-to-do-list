Abstract

In today's rapidly advancing digital world, productivity and personal organisation have become more important than ever before. People are increasingly relying on digital tools to manage their daily tasks, set priorities, and track the completion of activities. Traditional pen-and-paper to-do lists, while still widely used, lack the interactivity and accessibility that modern web-based applications can provide.

This project presents the design and development of a To-Do List Web Application built entirely using front-end web technologies — specifically HTML5, CSS3, and JavaScript. The application enables users to add, edit, delete, and mark tasks as complete, all through a clean and responsive user interface. Tasks are organised by priority levels (High, Medium, and Low) and can be assigned optional due dates to help users manage time-sensitive activities effectively.

One of the key features of this application is the use of the browser's localStorage API, which allows tasks to persist between sessions without requiring any server-side backend or database. This makes the application lightweight, fast, and easy to deploy on any standard web server or even run directly in a browser.

The application also includes filter functionality, allowing users to view tasks by their completion status or priority. A real-time statistics panel at the top of the application displays the total number of tasks, pending tasks, and completed tasks, providing users with a quick overview of their workload at a glance.

The interface has been designed to be visually appealing and intuitive, incorporating modern design principles such as gradient backgrounds, card-style task items, smooth animations, and colour-coded priority badges. The application is responsive and accessible across a range of devices including desktops, tablets, and mobile phones.

This report documents the full development lifecycle of the project — from the conceptualisation and objective setting to the design, implementation, and results. It also includes a discussion of the technologies used, the methodology followed, and a conclusion reflecting on the learning outcomes and future scope of the project.

Objective

The primary objective of this project is to design and develop a fully functional, interactive To-Do List application using core web technologies — HTML5, CSS3, and JavaScript — without the use of any external frameworks or libraries. The project aims to demonstrate the power of front-end web development in building practical, everyday tools that are both functional and visually appealing.

Specific Objectives:

  1. Task Management: To allow users to easily add new tasks, edit existing ones, and delete tasks that are no longer needed, providing full CRUD (Create, Read, Update, Delete) functionality.
  2. Priority Assignment: To enable users to assign a priority level — High, Medium, or Low — to each task, helping them focus on what matters most at any given time.
  3. Due Date Tracking: To allow users to associate a due date with each task, and to visually flag tasks that have passed their deadline as overdue.
  4. Task Filtering: To provide filtering options so that users can view all tasks, only pending tasks, only completed tasks, or tasks of a specific priority level.
  5. Data Persistence: To utilise the browser's localStorage API so that tasks are saved locally and remain available even after the browser is closed and reopened, without the need for a backend server.
  6. User Experience: To create a clean, intuitive, and responsive user interface that works seamlessly on all screen sizes and provides a pleasant experience for the user.
  7. Statistics Display: To show real-time statistics including the total number of tasks, number of pending tasks, and number of completed tasks.
  8. Educational Value: To serve as a learning exercise demonstrating the practical application of HTML structure, CSS styling, and JavaScript programming concepts including DOM manipulation, event handling, and Web Storage APIs.

Introduction

1.1 Background

The concept of a to-do list is as old as organised human activity itself. From handwritten notes on paper to printed planners, people have always needed a method to keep track of tasks, responsibilities, and goals. With the advent of the internet and the widespread adoption of personal computers and smartphones, the to-do list has evolved into a digital tool that is more powerful, accessible, and interactive than its paper-based predecessor.

Web-based to-do list applications are among the most commonly built beginner projects in programming education, and for good reason. They require the developer to work with nearly all fundamental concepts of web development — structuring content with HTML, styling it with CSS, and adding interactivity with JavaScript. At the same time, they are immediately useful and relatable, making them ideal as a learning project.

1.2 Problem Statement

In daily life, individuals often struggle to keep track of multiple tasks across different contexts — work, study, household, personal projects, and social commitments. Without a structured system for managing these tasks, it is easy to forget deadlines, lose track of priorities, and feel overwhelmed by an unorganised workload.

While many commercial task management tools exist (such as Todoist, Microsoft To Do, and Google Tasks), these platforms often require account registration, internet connectivity, and familiarity with complex interfaces. There is a genuine need for a simple, lightweight, browser-based tool that works entirely offline, requires no login, and focuses purely on the core functionality of managing a list of tasks.

1.3 Proposed Solution

This project proposes the development of a self-contained HTML To-Do List application that runs entirely in the web browser. The application is built using only standard web technologies — HTML5, CSS3, and vanilla JavaScript — and does not require any installation, server, or internet connection to function after the initial file download.

The application provides all essential task management features while maintaining simplicity and ease of use. It is designed to be visually clean and modern, with a colour scheme and layout that encourages regular use. The use of localStorage ensures that the user's data is preserved between browser sessions, providing a seamless and reliable experience.

1.4 Scope of the Project

The scope of this project covers the complete front-end development of a task management web application. The application is intended for individual use on a single device and browser. It does not include cloud synchronisation, multi-user support, or mobile app development, though these could be added in future iterations.

The project covers the following areas:

  • User interface design and development using HTML and CSS
  • Client-side scripting and dynamic content manipulation using JavaScript
  • Local data storage using the Web Storage API (localStorage)
  • Input validation and error handling
  • Responsive layout design for cross-device compatibility

Methodology

3.1 Development Approach

The project followed an iterative development approach, which allowed for gradual refinement of features and design throughout the development process. Rather than completing the entire application in one go, the project was broken down into smaller phases, each of which was implemented and tested before moving to the next. This approach made it easier to identify issues early and make adjustments without disrupting the overall structure of the application.

3.2 Development Phases

Phase 1 — Requirements Analysis:

The first step was to identify and define the core requirements of the application. This involved determining what features were essential (task addition, deletion, completion), what features would add significant value (priority levels, due dates, filtering), and what could be considered for future development (notifications, cloud sync).

Phase 2 — UI/UX Design Planning:

Before writing any code, the layout of the application was planned. A wireframe-style sketch was created to define the arrangement of elements — the header, statistics section, input area, filter bar, task list, and footer. Colour choices were made to create a visually appealing gradient theme using purple and blue tones.

Phase 3 — HTML Structure Development:

The HTML skeleton of the application was created, including all necessary elements — the container div, header section, stats boxes, input fields, select dropdown, filter buttons, task list container, and footer. Semantic HTML5 elements were used wherever applicable.

Phase 4 — CSS Styling:

The visual design was applied using CSS3. This included the gradient background, card-style task items, colour-coded priority badges, hover effects, transition animations, and responsive layout rules. CSS variables and modern properties such as flexbox, border-radius, and box-shadow were used extensively.

Phase 5 — JavaScript Functionality:

The core logic of the application was implemented in JavaScript. This phase included writing functions for adding tasks, toggling completion status, deleting tasks, editing tasks, filtering the task list, updating the statistics display, and managing localStorage for data persistence. Event listeners were attached to input fields and buttons to enable interactivity.

Phase 6 — Testing and Debugging:

After the core features were implemented, the application was thoroughly tested in different scenarios — adding multiple tasks, editing tasks with special characters, checking overdue detection accuracy, testing localStorage persistence by refreshing the browser, and verifying that all filter buttons work correctly. Any bugs identified were fixed promptly.

Phase 7 — Optimisation and Finalisation:

The final phase involved code cleanup, optimisation for readability and performance, and finalisation of the user interface. Comments were added to the code for clarity, and the overall layout was reviewed for consistency and polish.

Technologies Used

4.1 HTML5 (HyperText Markup Language)

HTML5 is the fifth and current major version of the HyperText Markup Language, the standard language for creating the structure of web pages. In this project, HTML forms the backbone of the application — it defines all the visible elements including the heading, input fields, buttons, dropdown menus, and the task list container. HTML5 introduces several improvements over earlier versions, including new semantic elements, native support for date input fields, and better form validation capabilities, all of which have been utilised in this project.

Key HTML5 features used in this project include the <input type="date"> element for due date entry, <select> for priority dropdown, and <input type="checkbox"> for task completion toggling.

4.2 CSS3 (Cascading Style Sheets)

CSS3 is the latest evolution of the Cascading Style Sheets language, used to control the visual appearance of HTML elements. CSS3 introduces advanced features such as transitions, animations, gradients, flexbox layout, media queries, and border-radius, all of which have been used extensively in this project.

The application's visual design was entirely crafted using CSS3. The gradient purple-blue colour scheme was achieved using the linear-gradient() function. Flexbox was used to lay out elements in rows and columns. The @keyframes rule was used to create a smooth slide-in animation for newly added tasks. Media queries ensure the layout is responsive on smaller screens.

4.3 JavaScript (ES6+)

JavaScript is the scripting language of the web, enabling dynamic and interactive behaviour on web pages. In this project, all the functional logic — adding tasks, filtering, editing, deleting, and persisting data — is handled by JavaScript. Modern ES6+ features such as arrow functions, template literals, destructuring, the spread operator, and JSON.parse / JSON.stringify for storage, have been used throughout the code.

4.4 Web Storage API (localStorage)

The Web Storage API provides mechanisms for storing key-value pairs in the browser. The localStorage object was used to save the tasks array as a JSON string on the user's browser. This ensures that all tasks are preserved even after the browser is closed, without requiring a backend database or server-side code. The storage limit for localStorage is typically 5–10 MB per domain, which is more than adequate for a personal task list.

System Design & Architecture

5.1 Application Architecture

The application follows a single-page architecture (SPA) pattern, where the entire application runs on a single HTML file. All rendering is handled dynamically by JavaScript — when the user interacts with the application, JavaScript updates the DOM (Document Object Model) in real time without requiring any page reload. This architecture results in a fast and smooth user experience.

The application is structured as three layers:

  • Presentation Layer (HTML + CSS): Defines the layout and visual appearance of the application.
  • Logic Layer (JavaScript): Handles all user interactions, data manipulation, and DOM updates.
  • Storage Layer (localStorage): Persists task data between sessions in the browser.

6.3 JavaScript Logic

The following JavaScript code handles all the core functionality of the application:

// Load saved tasks from localStorage on startup
let tasks = JSON.parse(localStorage.getItem('todoTasks')) || [];
let currentFilter = 'all';

// Save tasks array to localStorage
function saveTasks() {
  localStorage.setItem('todoTasks', JSON.stringify(tasks));
}

// Generate a unique ID for each task
function generateId() {
  return Date.now().toString(36) + Math.random().toString(36).substr(2);
}

// ADD a new task to the list
function addTask() {
  const input    = document.getElementById('taskInput');
  const priority = document.getElementById('prioritySelect').value;
  const dueDate  = document.getElementById('dueDateInput').value;
  const text     = input.value.trim();

  if (!text) {          // Validation: do not add empty tasks
    input.style.borderColor = '#e53935';
    setTimeout(() => input.style.borderColor = '#e0e4ff', 1500);
    return;
  }

  const task = {
    id: generateId(),
    text: text,
    priority: priority,
    dueDate: dueDate,
    completed: false,
    createdAt: new Date().toISOString()
  };

  tasks.unshift(task);  // Add new task at the beginning
  saveTasks();
  renderTasks();
  input.value = '';
  document.getElementById('dueDateInput').value = '';
}

// TOGGLE task completion status
function toggleTask(id) {
  const task = tasks.find(t => t.id === id);
  if (task) {
    task.completed = !task.completed;
    saveTasks();
    renderTasks();
  }
}

// DELETE a task by ID
function deleteTask(id) {
  tasks = tasks.filter(t => t.id !== id);
  saveTasks();
  renderTasks();
}

// EDIT a task's text using a prompt dialog
function editTask(id) {
  const task = tasks.find(t => t.id === id);
  if (!task) return;
  const newText = prompt('Edit task:', task.text);
  if (newText && newText.trim()) {
    task.text = newText.trim();
    saveTasks();
    renderTasks();
  }
}

// SET active filter and re-render
function setFilter(filter, btn) {
  currentFilter = filter;
  document.querySelectorAll('.filter-btn')
          .forEach(b => b.classList.remove('active'));
  btn.classList.add('active');
  renderTasks();
}

// CLEAR all completed tasks
function clearCompleted() {
  tasks = tasks.filter(t => !t.completed);
  saveTasks();
  renderTasks();
}

// CHECK if a task's due date has passed
function isOverdue(dueDate) {
  if (!dueDate) return false;
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  return new Date(dueDate) < today;
}

// RENDER tasks to the DOM based on current filter
function renderTasks() {
  let filtered = tasks;
  if (currentFilter === 'pending')   filtered = tasks.filter(t => !t.completed);
  if (currentFilter === 'completed') filtered = tasks.filter(t =>  t.completed);
  if (currentFilter === 'high')      filtered = tasks.filter(t => t.priority==='high');

  // Update statistics
  document.getElementById('totalCount').textContent = tasks.length;
  document.getElementById('pendingCount').textContent =
      tasks.filter(t => !t.completed).length;
  document.getElementById('completedCount').textContent =
      tasks.filter(t =>  t.completed).length;

  const list = document.getElementById('taskList');
  if (filtered.length === 0) {
    list.innerHTML = '<div class="empty-state">No tasks found.</div>';
    return;
  }
  list.innerHTML = filtered.map(task => `
    <div class="task-item ${task.completed ? 'completed' : ''}">
      <input type="checkbox" class="task-checkbox"
        ${task.completed ? 'checked' : ''}
        onchange="toggleTask('${task.id}')" />
      <div class="task-content">
        <div class="task-text">${task.text}</div>
        <span class="priority-badge priority-${task.priority}">
          ${task.priority}
        </span>
      </div>
      <button onclick="editTask('${task.id}')">✏️</button>
      <button onclick="deleteTask('${task.id}')">🗑️</button>
    </div>`).join('');
}

renderTasks(); // Initial render on page load

Conclusion

8.1 Summary

This project successfully demonstrates the design and development of a fully functional To-Do List web application using only HTML5, CSS3, and JavaScript — three of the most fundamental technologies in modern web development. The application fulfils all the stated objectives, providing users with a clean, intuitive, and feature-rich tool for managing their daily tasks.

The application allows users to add tasks with customisable priority levels and optional due dates, edit or delete tasks as needed, and mark tasks as complete. Tasks are organised and can be filtered by status or priority, giving users full control over how they view their workload. A real-time statistics panel provides an instant overview of the user's task progress, and the use of localStorage ensures that all data is preserved between sessions without requiring any server-side infrastructure.

8.2 Learning Outcomes

Through the development of this project, the following key skills and concepts were practised and reinforced:

  • Structuring web pages using semantic HTML5 elements and forms
  • Applying CSS3 for visual design, including gradients, flexbox, animations, and responsive layouts
  • Writing modular, readable JavaScript with clear function separation
  • Manipulating the DOM dynamically to create interactive user interfaces
  • Using the Web Storage API (localStorage) for client-side data persistence
  • Implementing input validation and user feedback mechanisms
  • Designing for usability and user experience (UX)

8.3 Challenges Faced

One of the challenges encountered during development was ensuring that the task list re-rendered correctly after every operation — including filtering, adding, editing, and deleting — without causing visual glitches or data inconsistency. This was resolved by implementing a centralised renderTasks() function that rebuilds the entire task list from the current state of the tasks array each time it is called. Another challenge was correctly detecting overdue tasks, which required careful handling of date comparisons in JavaScript to account for timezone and time-of-day differences.

8.4 Future Scope

The current version of the application is a strong foundation that can be extended in numerous ways:

  • Categories / Tags: Allow tasks to be grouped into custom categories such as Work, Study, Personal, etc.
  • Drag-and-Drop Reordering: Let users rearrange the order of tasks manually using drag-and-drop.
  • Browser Notifications: Use the Web Notifications API to send reminders for upcoming due dates.
  • Cloud Sync: Integrate with a backend (Node.js + MongoDB or Firebase) to synchronise tasks across devices.
  • Dark Mode: Add a dark theme toggle for better usability in low-light environments.
  • Export Feature: Allow users to export their task list as a PDF or CSV file.
  • Search Functionality: Add a live search bar to quickly find specific tasks by keyword.
