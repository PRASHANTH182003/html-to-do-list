Abstract

In today's rapidly advancing digital world, productivity and personal organisation have become more important than ever before. People increasingly rely on digital tools to manage their daily tasks, set priorities, and track the completion of activities. Traditional pen-and-paper to-do lists, while still widely used, lack the interactivity and accessibility that modern web-based applications can provide.

This project presents the design and development of a To-Do List Web Application built entirely using front-end web technologies — specifically HTML5, CSS3, and JavaScript. The application enables users to add, edit, delete, and mark tasks as complete, all through a clean and responsive user interface. Tasks are organised by priority levels (High, Medium, and Low) and can be assigned optional due dates to help users manage time-sensitive activities effectively.

One of the key features of this application is the use of the browser's localStorage API, which allows tasks to persist between sessions without requiring any server-side backend or database. This makes the application lightweight, fast, and easy to deploy on any standard web server or even run directly in a browser.

The application includes filter functionality, allowing users to view tasks by completion status or priority. A real-time statistics panel displays total tasks, pending tasks, and completed tasks, giving users an instant overview of their workload.

The interface has been designed to be visually appealing and intuitive, incorporating modern design principles such as gradient backgrounds, card-style task items, smooth animations, and colour-coded priority badges. The application is responsive and works across desktops, tablets, and mobile phones.

This report documents the full development lifecycle — from conceptualisation and objective setting to design, implementation, and results — along with a discussion of technologies used, the methodology followed, and a conclusion reflecting on learning outcomes and future scope.

Objective

The primary objective of this project is to design and develop a fully functional, interactive To-Do List application using core web technologies — HTML5, CSS3, and JavaScript — without any external frameworks or libraries. The project demonstrates the power of front-end web development in building practical, everyday tools that are both functional and visually appealing.

Specific Objectives

  1. Task Management: Allow users to add, edit, and delete tasks — providing full CRUD (Create, Read, Update, Delete) functionality.
  2. Priority Assignment: Enable users to assign a priority level — High, Medium, or Low — to each task, helping them focus on what matters most.
  3. Due Date Tracking: Allow users to associate a due date with each task, and visually flag overdue tasks in red.
  4. Task Filtering: Provide filtering so users can view All, Pending, Completed, or priority-specific tasks.
  5. Data Persistence: Use the browser's localStorage API so tasks remain available after the browser is closed — no backend required.
  6. User Experience: Create a clean, intuitive, and responsive UI that works on all screen sizes.
  7. Real-Time Statistics: Show live counts of Total, Pending, and Completed tasks at the top of the page.
  8. Educational Value: Serve as a learning exercise covering HTML structure, CSS styling, JavaScript DOM manipulation, event handling, and the Web Storage API.

Introduction

1.1 Background

The concept of a to-do list is as old as organised human activity itself. From handwritten notes on paper to printed planners, people have always needed a method to keep track of tasks, responsibilities, and goals. With the advent of the internet and the widespread adoption of personal computers and smartphones, the to-do list has evolved into a digital tool that is more powerful, accessible, and interactive than its paper-based predecessor.

Web-based to-do list applications are among the most commonly built beginner projects in programming education, and for good reason. They require the developer to work with nearly all fundamental concepts of web development — structuring content with HTML, styling it with CSS, and adding interactivity with JavaScript. At the same time, they are immediately useful and relatable, making them ideal as a learning project.

1.2 Problem Statement

In daily life, individuals often struggle to keep track of multiple tasks across different contexts — work, study, household, personal projects, and social commitments. Without a structured system, it is easy to forget deadlines, lose track of priorities, and feel overwhelmed by an unorganised workload.

While commercial task management tools exist (such as Todoist, Microsoft To Do, and Google Tasks), these platforms often require account registration, internet connectivity, and familiarity with complex interfaces. There is a genuine need for a simple, lightweight, browser-based tool that works offline, requires no login, and focuses purely on managing a list of tasks.

1.3 Proposed Solution

This project proposes a self-contained HTML To-Do List application that runs entirely in the browser using only HTML5, CSS3, and vanilla JavaScript. It requires no installation, server, or internet connection after the initial file download, and uses localStorage to preserve tasks between sessions.

1.4 Scope of the Project

The scope covers the complete front-end development of a personal task management web application, intended for individual use on a single device. It does not include cloud synchronisation or multi-user support, though those could be added in future iterations. The project covers:

  • User interface design and development using HTML and CSS
  • Client-side scripting and dynamic DOM manipulation using JavaScript
  • Local data storage using the Web Storage API (localStorage)
  • Input validation and user feedback mechanisms
  • Responsive layout design for cross-device compatibility

Methodology

3.1 Development Approach

The project followed an iterative development approach, breaking the work into smaller phases, each implemented and tested before moving to the next. This made it easier to catch issues early and adjust without disrupting the overall structure.

3.2 Development Phases

Phase 1 — Requirements Analysis:

The first step was identifying core requirements: essential features (add, delete, complete tasks), value-adding features (priority levels, due dates, filtering), and future-scope features (notifications, cloud sync).

Phase 2 — UI/UX Design Planning:

Before writing any code, the layout was planned — header, statistics panel, input area, filter bar, task list, and footer. A purple-blue gradient colour scheme was chosen for visual appeal.

Phase 3 — HTML Structure Development:

The HTML skeleton was created with all necessary elements: container div, header, stats boxes, input fields, priority dropdown, filter buttons, task list container, and footer. Semantic HTML5 elements were used wherever applicable.

Phase 4 — CSS Styling:

The visual design was applied using CSS3: gradient background, card-style task items, colour-coded priority badges, hover effects, transition animations, and a responsive flexbox layout.

Phase 5 — JavaScript Functionality:

All core logic was implemented in JavaScript: adding tasks, toggling completion, deleting, editing, filtering, updating statistics, and managing localStorage for data persistence.

Phase 6 — Testing and Debugging:

The application was tested in multiple scenarios — adding multiple tasks, editing tasks with special characters, checking overdue detection, verifying localStorage persistence across browser refreshes, and confirming all filter buttons work correctly. Bugs were fixed promptly.

Phase 7 — Optimisation and Finalisation:

The final phase involved code cleanup, comments for clarity, performance optimisation, and a final review of the user interface for consistency.

Technologies Used

4.1 HTML5 (HyperText Markup Language)

HTML5 is the standard language for creating web page structure. In this project, HTML defines all visible elements including the heading, input fields, buttons, dropdown menus, and the task list container. HTML5 improvements used include the native <input type="date"> element for due date entry, <select> for the priority dropdown, and <input type="checkbox"> for task completion toggling.

4.2 CSS3 (Cascading Style Sheets)

CSS3 controls the visual appearance of HTML elements and introduces advanced features such as transitions, animations, gradients, flexbox, media queries, and border-radius. The gradient purple-blue colour scheme uses the linear-gradient() function. Flexbox lays out elements in rows and columns. The @keyframes rule creates a smooth slide-in animation for newly added tasks. Media queries ensure responsiveness on smaller screens.

4.3 JavaScript (ES6+)

JavaScript enables dynamic and interactive behaviour on web pages. All functional logic — adding tasks, filtering, editing, deleting, and persisting data — is handled by JavaScript. Modern ES6+ features used include arrow functions, template literals, array methods (.find(), .filter(), .map()), and JSON.parse / JSON.stringify for storage.

4.4 Web Storage API (localStorage)

The localStorage object stores the tasks array as a JSON string in the user's browser. Tasks are preserved even after the browser closes — no backend database or server-side code is required. The typical storage limit is 5–10 MB per domain, which is more than adequate for a personal task list.

4.5 DOM (Document Object Model)

The DOM is a programming interface for HTML documents. It represents the page as a tree of objects so that JavaScript can programmatically access and manipulate content, structure, and style. In this project, document.getElementById(), document.querySelectorAll(), and innerHTML are used extensively to dynamically render and update the task list without any page reloads, making the application feel like a native desktop app.

4.6 Responsive Design

The application is built using a fluid, flexbox-based layout. The container has a max-width of 600px and uses percentage-based widths and CSS flexbox so that it adapts gracefully to any screen size — from a wide desktop monitor down to a small mobile phone screen. No external CSS framework (such as Bootstrap) was required; all responsiveness was achieved with native CSS3 only.

System Design & Architecture

5.1 Application Architecture

The application follows a Single-Page Architecture (SPA) pattern — the entire app runs inside one HTML file. JavaScript updates the DOM in real time without page reloads, producing a fast and seamless user experience. The application is structured as three logical layers:

  • Presentation Layer (HTML + CSS): Defines layout and visual appearance.
  • Logic Layer (JavaScript): Handles all user interactions and data manipulation.
  • Storage Layer (localStorage): Persists task data between browser sessions.

6.3 JavaScript – Core Logic (Part 1)

The following JavaScript handles data initialisation, saving, task creation, and deletion:

// Initialise: load from localStorage or start empty
let tasks = JSON.parse(localStorage.getItem('todoTasks')) || [];
let currentFilter = 'all';

// Persist the tasks array to localStorage
function saveTasks() {
  localStorage.setItem('todoTasks', JSON.stringify(tasks));
}

// Generate a unique ID for each task
function generateId() {
  return Date.now().toString(36) + Math.random().toString(36).substr(2);
}

// ADD a new task
function addTask() {
  const input    = document.getElementById('taskInput');
  const priority = document.getElementById('prioritySelect').value;
  const dueDate  = document.getElementById('dueDateInput').value;
  const text     = input.value.trim();

  if (!text) {   // Reject empty input
    input.style.borderColor = '#e53935';
    setTimeout(() => input.style.borderColor = '#e0e4ff', 1500);
    return;
  }

  tasks.unshift({           // Add to beginning of array
    id: generateId(),
    text, priority, dueDate,
    completed: false,
    createdAt: new Date().toISOString()
  });

  saveTasks();
  renderTasks();
  input.value = '';
  document.getElementById('dueDateInput').value = '';
}

// DELETE a task by id
function deleteTask(id) {
  tasks = tasks.filter(t => t.id !== id);
  saveTasks();
  renderTasks();
}

// TOGGLE completion status
function toggleTask(id) {
  const t = tasks.find(t => t.id === id);
  if (t) { t.completed = !t.completed; saveTasks(); renderTasks(); }
}

// EDIT task text
function editTask(id) {
  const t = tasks.find(t => t.id === id);
  if (!t) return;
  const n = prompt('Edit task:', t.text);
  if (n && n.trim()) { t.text = n.trim(); saveTasks(); renderTasks(); }
}

6.4 JavaScript – Filtering & Rendering (Part 2)

// SET active filter and re-render
function setFilter(filter, btn) {
  currentFilter = filter;
  document.querySelectorAll('.filter-btn')
          .forEach(b => b.classList.remove('active'));
  btn.classList.add('active');
  renderTasks();
}

// CLEAR all completed tasks at once
function clearCompleted() {
  tasks = tasks.filter(t => !t.completed);
  saveTasks();
  renderTasks();
}

// CHECK if a task's due date has already passed
function isOverdue(dueDate) {
  if (!dueDate) return false;
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  return new Date(dueDate) < today;
}

// FORMAT date for display
function formatDate(str) {
  if (!str) return '';
  return new Date(str).toLocaleDateString('en-GB',
    { day:'2-digit', month:'short', year:'numeric' });
}

// RENDER the task list based on currentFilter
function renderTasks() {
  // Apply filter
  const map = { all: () => true, pending: t => !t.completed,
                completed: t => t.completed,
                high: t => t.priority==='high',
                medium: t => t.priority==='medium',
                low: t => t.priority==='low' };
  const filtered = tasks.filter(map[currentFilter] || map.all);

  // Update stat counters
  document.getElementById('totalCount').textContent     = tasks.length;
  document.getElementById('pendingCount').textContent   = tasks.filter(t=>!t.completed).length;
  document.getElementById('completedCount').textContent = tasks.filter(t=> t.completed).length;

  const list = document.getElementById('taskList');
  if (!filtered.length) {
    list.innerHTML = '<div class="empty-state">No tasks found.</div>';
    return;
  }

  list.innerHTML = filtered.map(task => `
    <div class="task-item ${task.completed ? 'completed' : ''}">
      <input type="checkbox" ${task.completed?'checked':''}
             onchange="toggleTask('${task.id}')">
      <div class="task-content">
        <div class="task-text">${escapeHtml(task.text)}</div>
        <span class="priority-badge priority-${task.priority}">
          ${task.priority}</span>
        ${task.dueDate ? `<span class="due-date
          ${!task.completed && isOverdue(task.dueDate) ? 'overdue':''}">
          📅 ${formatDate(task.dueDate)}</span>` : ''}
      </div>
      <button onclick="editTask('${task.id}')">✏️</button>
      <button onclick="deleteTask('${task.id}')">🗑️</button>
    </div>`).join('');
}

// Prevent XSS when displaying user-entered text
function escapeHtml(t) {
  const d = document.createElement('div');
  d.appendChild(document.createTextNode(t));
  return d.innerHTML;
}

// Allow Enter key to add task
document.getElementById('taskInput')
        .addEventListener('keypress', e => { if(e.key==='Enter') addTask(); });

renderTasks(); // Initial render on page load

Conclusion

8.1 Summary

This project successfully demonstrates the design and development of a fully functional To-Do List web application using only HTML5, CSS3, and JavaScript — three of the most fundamental technologies in modern web development. The application fulfils all stated objectives, providing users with a clean, intuitive, and feature-rich tool for managing daily tasks.

Users can add tasks with customisable priority levels and optional due dates, edit or delete tasks as needed, and mark tasks as complete. A real-time statistics panel gives an instant overview of workload, and localStorage ensures all data is preserved between sessions without any server-side infrastructure.

8.2 Learning Outcomes

Through this project, the following skills and concepts were practised and reinforced:

  • Structuring web pages using semantic HTML5 elements and form controls
  • Applying CSS3 for visual design including gradients, flexbox, animations, and responsive layouts
  • Writing modular, readable JavaScript with clear function separation
  • Dynamically manipulating the DOM to create interactive user interfaces
  • Using the Web Storage API (localStorage) for client-side data persistence
  • Implementing input validation and user feedback mechanisms
  • Designing for usability and user experience (UX)

8.3 Challenges Faced

A key challenge was ensuring the task list re-rendered correctly after every operation — adding, editing, deleting, filtering — without data inconsistency or visual glitches. This was resolved by implementing a single centralised renderTasks() function that rebuilds the entire list from the current state of the array each time it is called. Correctly detecting overdue tasks also required careful JavaScript date comparison to account for timezone differences.

8.4 Future Scope

  • Categories / Tags: Group tasks into custom categories (Work, Study, Personal).
  • Drag-and-Drop Reordering: Let users manually rearrange tasks.
  • Browser Notifications: Send reminders for upcoming due dates via the Web Notifications API.
  • Cloud Sync: Integrate a backend (Firebase / Node.js + MongoDB) to sync across devices.
  • Dark Mode: Add a dark theme toggle for low-light environments.
  • Export to PDF / CSV: Allow users to download their task list.
  • Search Bar: Quickly find specific tasks by keyword.
